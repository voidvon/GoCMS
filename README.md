# GoCMS 静态 CMS

Go + SQLite 内容服务、React 管理后台、Go 模板静态发布。

## 目录

- `backend/`：Go 模块，`cmd/site` 服务、`cmd/generate` 发布、`cmd/migrate` 导入、`cmd/reset-password` 密码重置。
- `backend/templates/`：无主题包时使用的默认 Go 模板；页面布局在主题模板中维护。发布版会把默认模板编入可执行文件，并在首次运行时初始化到外部目录，之后保留外部修改。
- `frontend/`：Vite + React 管理后台，shadcn Base UI Nova；官方组件保持原样，业务封装放 `src/components/app/`。
- `assets/theme/<id>/`：已安装模板组的模板和自定义文件，属于可更改的外部资源；升级程序不会覆盖它。`theme.json` 中的 `template_groups` 映射模板文件用途。
- `assets/images/`：内容封面、正文和详情介绍图，属于运行时业务资源，不纳入 Git；服务直接读取，不参与发布复制。
- `web/`：生成的 HTML 和 Sitemap.xml，不纳入 Git；发布只替换此目录。
- `data/`：SQLite 数据库、发布状态及发布锁；不可作为静态网站根目录。
- `legacy/`：原 ASP、Access、原模板和 IIS 配置本地归档；不纳入 Git，不参与 Go 运行。

## 本地运行

在项目根目录分别打开两个终端：

```sh
make backend
make frontend
```

后台：`http://127.0.0.1:1244/admin/`，网站：`http://127.0.0.1:18080/`。
后台页面内“网站发布”支持全站重新生成；内容编辑支持“仅保存”和“保存并发布”。隐藏内容会自动提交发布任务。已有任务运行时，新的保存发布请求会排队，在当前任务结束后再读取最新数据生成。

内容列表每条记录的“更新 HTML”支持单条更新：使用已保存数据，重新生成该内容详情、所属栏目及全部父级栏目的所有分页/封面页，以及首页，覆盖所有启用语言（含独立语言站点）。链接栏目跳过静态生成并继续更新其父级。栏目层级、模板、路由和分页均沿用数据库配置；其他内容详情、无关栏目和网站索引保持原样。索引可在“网站发布”中单独生成；“保存并发布”仍执行全站发布。此操作需要当前站点的“网站发布”权限，且目标内容必须在当前站点及授权栏目范围内；接口为 `POST /api/admin/publish/content`，JSON 参数 `{"id":内容ID}`，完成后返回生成结果，已有发布任务时返回 409。

发布路由记录保存于 `data/publish-pages.json`（其他站点为 `publish_<site_id>-pages.json`），用于单条更新时清理旧详情地址、过期分页，并在内容移动后更新原栏目及其父级。升级后先执行一次全站发布，可为全部内容建立完整记录；没有旧记录时，无法追溯此前改名或移动前的地址，可通过全站发布清理。单条更新先保留无关页面并暂存全部语言输出，全部准备成功后再切换目录；切换或路由记录保存失败会尝试恢复已切换目录。

```sh
make generate  # 命令行全站生成
make test      # Go 测试/vet + 前端构建
make release-dry-run  # 查看下一次 Release 版本，不修改仓库
make release          # 更新版本、创建 tag 并发布 GitHub Release
```

后台“模板管理”以模板组为统一入口，按首页、封面、列表、内容、标签和其他模板分类管理，并提供“自定义文件”区维护模板引用的 CSS、JS 和图片。模板组支持切换、导入和导出；模板包为 ZIP，根目录包含 `theme.json`、`templates/` 和 `assets/`，资源按需放在 `assets/css/`、`assets/js/`、`assets/skin/`、`assets/images/`。`theme.json` 可用 `template_groups` 显式绑定 HTML 文件用途，没有该字段时兼容按文件名识别。切换前会检查全局页面绑定的模板，以及每个分类当前类型对应的 `list_template`、`cover_template` 或 `detail_template`，模板组需提供这些路径对应的模板。导入后模板组保存在 `assets/theme/<id>/`，切换会记录到 `data/theme.json` 并自动重新生成网站。模板包不包含数据库、业务图片或 `web/`。

模板数据调用和受限帝国 `[e:loop]` 迁移语法见 [模板数据调用说明](docs/template-data-calls.md)；AI 自动化接入与 API Key 规范见 [AI Agent 操作指南](docs/ai-agent-guide.md)。

版本号保存在 `frontend/package.json`，从 `0.1.0` 开始。`make release` 首次发布 `v0.1.0`，之后每次递增 patch 版本；`0.1.99` 之后进入 `0.2.0`。发布前需要保持 Git 工作区干净，并确保已通过 `gh auth login` 登录 GitHub，且已安装 `zip` 命令。Release 每个平台上传一个 `gocms-<tag>-<os>-<arch>.zip` 压缩包，包内包含对应平台的单文件可执行文件。更新器使用 Go 标准库解压 ZIP，不依赖 Linux 安装第三方工具。可以使用 `RELEASE_REMOTE=upstream make release` 指定其他 Git remote。

后台“关于 GoCMS”中的“检查更新”会读取 GitHub 最新 Release。服务检测到对应平台的新版本后会下载 ZIP 压缩包、解压可执行文件、替换当前程序并自动重启；主题、模板、业务图片、数据库和已发布网站目录都不会被更新流程覆盖。`v0.1.1` 的旧更新器只支持裸可执行文件，升级到 ZIP 版本前需要手动替换一次程序。

## 后台用户与权限

登录保护：15 分钟内账号或 IP 关联失败达到 5 次后返回 429；被限流请求不会增加失败记录或延长限制。保护查询失败时返回 503。`POST /api/admin/logs/clear` 仅允许超级管理员会话调用，参数 `before` 接受 RFC3339 瞬时时间（后台按操作者本地时间的当日 00:00 提交）或历史沿用的 UTC 日期 `YYYY-MM-DD`（删除范围包含该日）。两类日志在同一事务内清理，但最近 15 分钟登录记录保留，以免清理解除登录限制。

“用户与权限”提供账号、用户组、停用和模块权限管理。首次升级权限表时，已有管理员保留超级管理员权限；以后新增普通账号必须选择用户组。修改账号会撤销该账号的会话及 API Key，最后一个启用的超级管理员不可删除或停用。

内容权限参考帝国 CMS `eadmin/admin/user/AddGroup.php` 的新增、修改、删除和审核权限，以及 `AddUser.php` 的 `adminclass` 栏目授权。GoCMS 使用自己的通用数据模型，不读取帝国 CMS 的运行表。

- “内容管理”提供浏览权限；新增、修改、删除、审核分别授权。升级前仅勾选“内容管理”的普通用户组需显式补选操作权限。
- 未授予审核权限的编辑只能保存隐藏内容，不能修改已经公开的内容；审核人员需要同时具有内容管理、修改和审核权限，编辑并开启“公开展示”后按原发布流程生成网站。隐藏不等于独立待审核状态，本版本不包含多级审核或版本管理。
- 账号可选择全部栏目或指定栏目，约束内容列表、详情、保存和删除。指定栏目不隐式包含下级栏目，空选择表示无内容范围；移动内容要求同时拥有原栏目及目标栏目的权限。栏目结构配置权限仍由“栏目管理”模块独立控制。
- 旧账号默认全部栏目，超级管理员不受栏目范围限制；指定栏目账号不会自动获得以后新增栏目的权限。

## 多语言与后台显示语言

语言的三个标记互相独立，参考旧版后台的模型（`languages.is_default` 是后台管理语言，`language_sites.is_primary` 是主站点）：

- **主站语言**（`gocms_language.is_default`）：生成在网站根路径 `/`，同时是内容基准语言——主站语言的标题/栏目名称必填，其他语言留空时按兜底语言回退。切换主站语言只影响前台生成与基准字段。
- **后台显示语言**（`gocms_language.is_admin_default`）：后台“分类”与“内容”列表默认按该语言显示，方便维护人员使用自己的母语；全站只有一种，设为后台显示语言时会自动启用该语言。管理员仍可在「多语言」页面顶部临时切换自己浏览器使用的语言，选择保存在本机浏览器（`gocms_admin_lang`），旁边的“跟随后台默认”可清除本机选择。
- **兜底语言**（`gocms_language.is_fallback`）：其他语言缺字段时逐字段补充。

分类与内容列表按当前后台显示语言取数，翻译数据始终来自各自的翻译表，因此切换显示语言不会改写基准语言的内容。主站语言、后台显示语言和兜底语言都不可删除；升级时若没有后台显示语言，会自动回填为主站语言，保持旧行为。

`GET /api/search` 的关键词匹配基准字段与**当前语言**的译文（标题、摘要、正文），所以中文站点可以用中文关键词搜到以英文为基准语言的内容，而英文站不会因为某条内容只有中文或西语译文就被搜出来；返回结果仍按请求的 `lang` 套用译文。

## 发布规则

后台“操作日志”参考帝国 CMS 的 `insert_dolog` 和 `ListDolog.php`，记录通过权限检查后的后台 POST、PUT、PATCH、DELETE 请求，包括账号、时间、IP、接口路径及响应状态。用户组需授予“查看操作日志”权限，超级管理员默认可查看；支持账号精确筛选和分页。登录/退出、被权限拦截的请求不在此日志范围内，不保存正文或查询参数。日志记录失败会写入服务日志，不回滚已完成的操作；发布请求成功不代表异步发布任务完成。

| 数据 | 模板绑定 | 文件 |
| --- | --- | --- |
| 站点首页 | 当前模板组首页模板 | `/index.html` |
| 公开内容 (`visible=1`) | 所属分类的 `detail_template` | 使用分类配置的详情目录和文件名规则 |
| 栏目内容（包含后代内容） | 分类的 `list_template` | 使用分类配置的列表目录和文件名规则 |
| 栏目封面页 | 分类的 `cover_template` | 使用分类配置的栏目目录和文件名规则 |
| 留言表单 | `message` | `/msg.html` |
| 搜索页面 | `search` | `/search.html` |
| 404 页面（可选） | `notfound` | `/404.html`（语言目录为 `/es/404.html`） |
| 已生成页面 | 内置生成器 | `/Sitemap.xml`、`/sitemap.html` |

每个分类可以设置栏目类型。列表式栏目使用 `list_template`，按每页数量生成分页；第一页同时生成基础文件名和第一页文件名，后续页面使用配置的分页规则。封面式栏目使用 `cover_template`，只生成一页，文件名和目录均来自分类配置。首页直接使用当前模板组对应的首页文件（`index.html`），留言和搜索页面使用全局模板绑定；栏目名称、页面文案、列表结构和图片展示规则由主题模板决定。网站地图从实际生成的地址产生。

`notfound` 绑定是可选的：主题提供 404 模板时按语言生成 `404.html`，未命中的路径由服务端返回该页面（同一语言目录优先，例如 `/es/...` 使用 `es/404.html`），API 路径仍返回纯文本；主题没有 404 模板时保持原有的纯文本响应，主题校验与发布都不会失败。

404 模板会收到 `is_404=true`、`page_type=404`、`seo_title=404`、`seo_robots=noindex, follow`、`seo_canonical=""`。主题应优先使用这些字段，而不是让通用 head 回退到首页 title/canonical：

```go
{{if .is_404}}
  <title>{{.seo_title}} | {{setting "site_name"}}</title>
  <meta name="robots" content="{{.seo_robots}}">
{{else}}
  <!-- 正常页面的 title / canonical / robots -->
{{end}}
```

服务端还会对所有 4xx/5xx 响应设置 `Cache-Control: no-store`，对 HTML 错误设置 `X-Robots-Tag: noindex, follow`；直接访问 `/404.html` 也带同样的响应头。`404.html` 与各语言 404 页面不会进入 `sitemap.xml`、`sitemap.html` 或 `llms.txt`。

所有内容统一使用 `gocms_content`，所有栏目统一使用 `gocms_category`，留言统一使用 `gocms_message`。每个分类保存自己的栏目类型、列表/封面模板、详情模板、静态目录和文件名规则；内容只保存所属分类 ID，发布器按分类解析路径。新建分类使用通用默认配置，导入器负责把外部系统的数据转换为这些统一字段。运行时只读取 `gocms_*` 表，不读取外部系统的表结构。

错误响应（4xx/5xx）始终使用 `Cache-Control: no-store`，避免文件补传或页面修复后仍被浏览器/反向代理缓存。反向代理配置只应对成功响应设置长缓存，不要对 `uploads`、`images`、`css`、`js` 等 location 使用 `add_header ... always`。

发布写入前默认对 `.html` 页面做 HTML 压缩（去除注释、折叠标签间空白，`<pre>`、`<textarea>` 及内联 `script`/`style` 内容保持原样）；站点设置 `html_minify=0` 可关闭。`sitemap.xml`、`llms.txt` 等非 HTML 文件不处理。

主题的独立 `css`、`js` 文件在服务时压缩并按文件修改时间缓存，不修改主题源文件；站点设置 `asset_minify=0` 可关闭。HTML 与 CSS/JS 的开关相互独立。

生成使用一致的 SQLite 读事务快照。先完成所有模板渲染和 UTF-8 检查，再向临时目录写入新 HTML 和站点地图，最后切换 `web/`。新目录只包含本次生成结果，因此隐藏/删除内容及过期分页会清理；独立资源目录不被修改。未知模板标签或模板错误会终止发布，保持旧站点。发布锁用于防止 CLI/API 并发写入。

目录切换使用同文件系统的两次 rename；切换间可能存在极短的无目录窗口，并非整个站点的单次原子交换。安装失败会尝试恢复 `web.previous`。若进程在切换时中断并留下 `web.previous`，先检查 `web/` 是否完整，再恢复或归档备份后重新发布。发布结果保存在 `data/publish.json`，后台也会展示生成数量、状态和失败原因。

模板与自定义 HTML 片段属于受信任的管理员内容。普通字段会 HTML 转义，富文本正文按 HTML 输出。图片统一使用 `/images/文件名`，服务先查找 `assets/images/`，再查找当前主题的 `images/` 目录；外部数据的资源路径只在导入阶段转换。

## 访问统计

本地测试可用 `python3 scripts/seed-access-logs.py --reset` 生成多域名、多状态、多来源的访问与错误记录（默认站点 1，可用 `--site`、`--hosts` 指定）；`--ignore` 可预置忽略路径。脚本只写 `gocms_access_log` 与 `gocms_access_log_ignore`，不修改内容、分类、模板或站点设置。

仪表盘按站点统计前台访问量和错误，数据来自 `gocms_access_log`。站点通过请求 Host 解析（与前台一致，独立语言域名归入所属站点），后台只显示当前所选站点的数据；不同站点之间不共享任何统计。

- 记录范围：返回 HTML 的 2xx 页面访问，以及所有 4xx/5xx 响应（包括缺失的 CSS、JS、图片等资源）。成功的静态资源请求、3xx 跳转、`/api/` 和 `/admin/` 请求不记录，避免噪声。只记录 GET。
- 每条记录保存请求域名（`host`）、路径、查询串（截断到 200 字符）、状态码、类型、客户端 IP、User-Agent 摘要、客户端类型（浏览器/爬虫/工具/其他）、设备类型（桌面/移动/平板/其他）、来源地址与来源分类（站内/站外/直接访问/无效 Referer）。`host` 保留实际请求域名（包括 `www.` 和独立语言域名），用于在多域名站点中区分错误来源；历史记录升级前为空，后台回退显示当前站点主域名。站内判定不只检查域名：错误请求还要求 Referer 指向该站点真实存在的 HTML 页面（目录 URL 需有 `index.html`），否则记为 `invalid`，不计入“站内死链”。现代浏览器提供的 `Sec-Fetch-Site` 也会参与判定。
- 仪表盘展示今日访问、24 小时访问与访客、新访客、PC/移动访客、404 数量、错误总数、站内死链地址数/命中数、累计页面、热门页面、按“域名 + 路径 + 状态”归并的错误列表和状态码分布。错误列表与访问明细都会显示请求域名；错误列表和热门页面在卡片内滚动到底部时自动加载更多。错误类型统计位于错误卡片右侧，不占用列表下方空间。`internal_404_paths` 是按 URL 去重后的站内死链数，`internal_404_errors` 是命中次数，二者不要混用。
- 错误列表支持按路径忽略：规则只保存路径，不带域名，因此同一路径在站点主域名、`www` 别名和独立语言域名上全部生效；完整 URL 会被规范化为路径。忽略后该路径不再进入错误总数、404/站内死链指标、错误类型分布和错误归并列表，但原始访问明细保留用于审计；忽略规则独立于访问日志保留期。
- “访问统计”页面可按时间范围、类型、状态、客户端、设备、来源、路径、IP 和关键字过滤，查看错误归并列表或逐条访问明细，并按当前筛选条件清空日志。
- 权限：“访问统计”查看权限为 `traffic`，清空权限为 `traffic.clear`；超级管理员默认全部可用。清空操作会写入操作日志。
- 保留策略：默认保留 3 天，服务启动时及之后每 30 分钟清理过期记录；用 `-access-log-days` 调整保留天数。自然日边界默认跟随系统时区，可用 `-timezone Asia/Shanghai` 指定 IANA 时区；时间戳按 UTC 存储与传输，界面统一按浏览器所在时区显示。
- 接口：`GET /api/admin/access-logs`（分页明细，`page`、`page_size`，过滤参数同页面）、`GET /api/admin/access-logs/errors`（按域名、路径与状态归并，支持 `limit`、`offset`、`sort=hits|recent`）、`GET /api/admin/access-logs/pages`（热门页面，支持 `limit`、`offset`）、`GET/POST/DELETE /api/admin/access-logs/ignores`（查看、添加、取消路径忽略；POST 传 `{"path":"..."}`，DELETE 传 `?path=...`）、`DELETE /api/admin/access-logs`（按同一组过滤参数清理）；`GET /api/admin/stats` 的 `access` 字段提供仪表盘指标。

## 留言通知

前台通过 `/api/messages`、`/api/feedback` 提交的留言，可以按站点推送到飞书（Feishu）或国际版 Lark 的群自定义机器人。

- 配置入口：后台「反馈信息列表 → 通知设置」，填写机器人 Webhook 地址并开启通知；同一后台可切换站点，各站点互不影响。
- 地址校验：必须是 `https`，域名 `open.feishu.cn` 或 `open.larksuite.com`，路径以 `/open-apis/bot/v2/hook/` 开头且带 token；保存时会去掉多余的查询串和锚点。
- 推送内容为文本消息，包含站点、分类、标题、姓名、电话、邮箱、留言正文（截断到 2000 字）、来源 IP 和提交时间。
- 推送在留言入库并响应访客之后于后台 goroutine 中执行（8 秒超时），Webhook 不可达或超时都不会拖慢或影响访客提交。
- 每条留言记录推送结果：`notification_status` 取 `pending`（已入库待推送）、`sent`、`failed`、`disabled`（未启用），失败原因写入 `notification_error`（截断到 500 字），成功时间写入 `notified_at`；留言详情弹窗展示这些字段。升级前已存在的历史留言状态为空，表示从未排队推送。
- 配置保存在 `gocms_site_setting` 的 `message_webhook_url` 和 `message_webhook_enabled` 两个键下，属于站点级设置，不影响静态发布。
- 权限：沿用留言模块的 `messages` 权限；未登录或无权访问该站点的账号无法读写通知设置。
- 接口：`GET /api/admin/messages/webhook`（读取设置）、`PUT /api/admin/messages/webhook`（保存，可只传 `enabled` 或 `webhook_url`）、`POST /api/admin/messages/webhook/test`（发送测试消息，不传地址则用已保存的地址）。
- 已知限制：未实现机器人的签名校验，也未提供失败重发按钮；若机器人开启了「签名校验」，请先关闭，否则推送会以飞书返回的错误原因记录为发送失败。

### 后台通知

后台侧边栏顶部的通知铃铛汇总后台任务失败，推送失败不再只藏在留言详情里。

- 飞书推送失败时写入一条通知（标题「留言飞书通知发送失败」，正文包含留言标题与飞书返回的原因），同一站点未读的同类通知会合并为一条并累计次数（`occurrences`），避免机器人故障时刷屏。
- 铃铛显示未读数角标，登录后首次加载若有未读会额外弹出一次提示（同一条通知每个浏览器会话只提示一次，刷新不会反复打扰）；弹窗内按未读优先、时间倒序列出，可「全部已读」或点单条已读。
- 点击通知会跳转到对应页面（当前为「反馈信息列表」），站点切换后角标按当前站点重新统计；页面保持打开时每 60 秒刷新一次角标。
- 通知按站点隔离，已读历史最多保留 50 条，超出的最旧记录会被清理。
- 权限：登录后即可读取与标记自己有权访问站点的通知，不需要额外权限项。
- 接口：`GET /api/admin/notifications?limit=50`（返回 `items` 与 `unread`）、`POST /api/admin/notifications`（`{"all":true}` 或 `{"ids":[...]}` 标记已读，返回剩余未读数）。

## 时间显示

后台所有时间都按访问者浏览器所在时区渲染，不再显示服务器时区或 UTC。

- 相对时间：刚刚、N 分钟前、N 小时前、昨天 HH:mm、前天 HH:mm、本周（周三 HH:mm）、上周（上周三 HH:mm）、本月 D 日 HH:mm、上月 D 日 HH:mm；更早的同年时间显示 `M月D日 HH:mm`，跨年显示 `YYYY年M月D日 HH:mm`，未来时间直接显示具体日期时间。
- 悬停任意时间可看到该时区下的完整时间 `YYYY-MM-DD HH:mm:ss`。
- 接口统一输出带时区的 RFC3339 瞬时时间，`backend/internal/timestamps` 负责把 SQLite 里遗留的挂钟时间（UTC 默认值与服务器本地时间两类）转换成瞬时时间；前端只保留 `frontend/src/lib/time.ts` 一套解析与格式化规则，页面统一通过 `TimeText` 组件渲染。
- 例外：内容“发布时间”由编辑填写且不带时区，按字面展示，不做时区换算。

## 旧语言前缀跳转

语言配置调整后（例如把某语言从子目录改为独立域名或站点根路径），搜索引擎与历史链接仍会请求旧地址，例如根路径服务的英文站点会持续收到 `/en/products/xxx/`。服务直接对这类地址做 301 跳转，不需要在 Nginx 配置 rewrite。

- 判定依据是语言表：语言代码，以及独立域名语言（`site_mode=standalone`）配置的 `path_prefix`，都视为不应出现在生成 URL 中的旧前缀；子目录语言的前缀是真实路径，不参与跳转。
- 只有在“原地址在该站点不可用、去掉前缀后的地址存在”时才跳转，并保留查询串。因此正常 URL 不受影响，真实存在的 `/en/...` 目录也不会被遮蔽。
- 站点按请求 Host 解析，独立语言域名（如 `www.example.cn`）上的旧前缀同样会被去掉；跳转只作用于 GET/HEAD。

## 生产运行

```sh
make build
cd backend
../bin/site -addr 127.0.0.1:18080
```

Go 同时提供 `/admin/`（发布版内置前端）、`/api/` 和公开静态站点。`/images/` 依次映射到 `assets/images/` 和当前主题的 `assets/images/`，`/css/`、`/js/`、`/skin/` 映射到当前主题对应目录，网站页面读取 `web/`。发布不复制图片，也不创建符号链接。Nginx 可直接反向代理 Go；如果由 Nginx 提供静态文件，应按相同顺序配置这些资源目录，页面映射到 `web/`。外网部署由反向代理提供 HTTPS。

命令行发布和 Go 服务支持 `-assets` 指定资源根目录，并支持 `-theme` 指定主题目录覆盖活动主题配置。没有覆盖参数时，程序从 `assets/theme/` 和 `data/theme.json` 解析活动主题；没有活动记录时选择已安装主题中的第一个。服务还支持 `-access-log-days`（访问日志保留天数，默认 3）和 `-timezone`（访问统计自然日边界使用的 IANA 时区，默认系统时区）。发布版可执行文件会把管理后台和默认 Go 模板编入自身，模板首次运行时写入外部 `templates/`；Release 单文件不包含主题目录，部署时需要在外部 `assets/theme/<id>/` 提供主题资源，修改后直接生效。备份应包括 `data/site.db`、运行时的 `assets/images/`、`assets/theme/` 和 `templates/`。

登录仅接受 Argon2id。新导入 Access 后必须重新设置管理员密码：

```sh
cd backend
go run ./cmd/reset-password -username gocms -password '新的密码'
```

后台的分类页面统一维护栏目树，内容编辑从统一分类树中选择所属栏目，发布器读取统一内容、分类和 SEO 字段生成页面。新增业务图片应保存到 `assets/images/`，主题图片应保存到当前主题的 `images/` 目录，数据库字段统一使用 `/images/文件名`。
