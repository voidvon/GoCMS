# 平台共享 Google 会员登录

入口：**平台管理 → 第三方登录**，地址 `/admin/member-login`，仅超级管理员的后台会话可访问。配置不随后台当前站点切换。Google 登录用于前台会员，不用于后台管理员登录。

## 一次配置，全部站点共享

平台统一管理一套 Google Client ID、Client Secret、登录总开关和首次登录自动注册策略。所有启用站点使用这一套凭据；无需逐站填写，也不存在站点覆盖平台配置的规则。关闭后全部站点隐藏 Google 登录及账号绑定区域，并拒绝新的登录和进行中的授权；已有会员会话仍按既有规则有效。

1. 超级管理员在页面的“登录加密密钥”生成密钥，并下载备份。恢复已有数据库时应导入原密钥，不能重新生成。
2. 在“多站点”管理配置各站点域名、别名及独立语言域名。
3. 在 Google Auth Platform 创建**一个 Web 应用 OAuth 客户端**，完成品牌信息、隐私政策、域名验证及 Google 要求的发布流程。
4. 在平台页面填写一次 Client ID、Client Secret 并保存。
5. 复制“全部站点的授权回调地址”，加入这个 Google 客户端的“已获授权的重定向 URI”。每个地址形如 `https://site.example/api/auth/google/callback`。
6. 在列表中的站点公开域名下打开平台后台，点击“测试当前域名”。总开关关闭时也可测试，测试不创建会员或会员会话。
7. 开启平台总开关并保存，使用普通 Google 账号验证各站点。

**共享凭据不等于只登记一个域名。** Google 要求每次授权的回调地址与客户端登记地址精确匹配。新增或修改域名后，需把新增回调地址加入同一个 Google 客户端，无需再建客户端或重复填写凭据。正式域名和品牌审核仍需在 Google 控制台完成，后台测试成功不代表已经获得生产发布资格。

回调目录来自启用站点已配置的主域名、别名、独立语言域名，以及域名归属匹配的站点公开地址 `site_url`。生产地址使用 HTTPS；本地可在已有站点公开地址设置中配置 `http://localhost:端口`、`http://127.0.0.1:端口` 或 `http://[::1]:端口`。不能从任意请求 Host、`site_id` 参数或通配域名构造回调地址；通配域名应先添加具体域名。反向代理应覆盖客户端提供的转发头，保留正确的公开 Host 和协议。

## 共享会员身份与站点权限

- 相同 Google `sub` 在整个平台关联同一个会员账号，在另一个站点登录时复用此会员，不创建重复账号，也不按邮箱自动合并。
- 首次登录在允许自动注册且邮箱已验证、未冲突时创建无本地密码的会员。已有邮箱账号须先登录原账号，在 `/shop/account` 输入当前密码后绑定 Google。
- 首次加入一个站点，仅分配该站点的默认会员组；其他站点的 VIP、会员组及订单权限不会被复制。
- Google 身份绑定、解绑是平台级操作。账号安全页明确提示对全部站点生效；有本地密码的会员需要确认密码，无本地密码的会员不能解绑最后的 Google 登录方式，可联系管理员设置本地密码后再解绑。
- 总开关的自动注册策略只控制创建新会员；已绑定的会员仍可在各启用站点登录，并按站点取得默认会员组。
- 各域名继续创建本站会员会话，遵循同一会员的会话上限、停用和撤销规则。不同主域名不会自动共享浏览器 Cookie，不属于免交互跨域 SSO；用户在新域名点击 Google 登录后使用同一会员账号。
- 退出只退出当前本站会话，不退出 Google 或其他域名的会话。全账号撤销会话仍由现有会员安全操作管理。

## 凭据与授权安全

Client Secret 留空保留已有值；读取接口只返回是否已配置。独立服务级密钥 `data/member-login.key`（0600）保护数据库中的 AES-GCM 密文，和支付密钥分开管理。新平台凭据使用平台加密作用域；迁移的旧凭据保留原加密作用域直到管理员更新密钥值。超级管理员可生成、导入、下载备份；API Key 和站点管理员无权访问平台登录配置。

密钥和备份不得进入公开目录或版本库。更新不会覆盖已有密钥文件。恢复时需保留数据库及对应密钥；文件损坏或权限异常会使启动失败，不能带着未知密钥继续运行。后台审计仅记录操作路径、状态等，不记录请求体、凭据或令牌。

授权采用服务器端 OIDC 授权码流程及 PKCE，仅申请 `openid email profile`。后端验证令牌签名、签发方、受众、有效期、authorized party 与 nonce。一次性事务有效期十分钟，绑定发起浏览器、实际站点、精确来源和平台配置版本。站点 A 的事务不能在站点 B 完成，即使两站共享凭据；返回地址只允许站内路径。对应提供商的平台配置更新会使其未完成的事务失效。

## 旧版配置兼容

启动时幂等创建 `gocms_platform_oauth_config`、`gocms_platform_identity`，给原授权事务补充精确来源字段。旧 `gocms_member_oauth_config` 和 `gocms_member_identity` 保留用于兼容，不再作为活动配置入口。

- 仅有一套旧站点凭据时自动沿用为平台配置，不需要明文解密或修改原密文。
- 存在多套旧凭据时保持平台默认关闭，在平台页面明确选择沿用哪一套，或填写一套新凭据。不会依据固定站点 ID、站点顺序或默认站点静默选择。
- 首次登录时，仅把能唯一对应会员的旧绑定提升为平台绑定；若同一 Google 身份曾关联多个会员，返回账号冲突，不自动合并。成员可使用原账号密码登录后解除旧绑定，再绑定需要的账号；无本地密码时先由管理员设置。
- 删除站点不会删除平台凭据或其他站点仍使用的共享身份；删除会员账号时身份随会员外键清理。
- 旧版 OAuth 单独填写的公开地址不再作为站点配置覆盖项。若使用非默认端口，请在已有站点公开地址 `site_url` 中保留该地址，并核对平台列出的回调目录。
- 升级前已发起的旧授权需重新开始。

## 接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/admin/member-login` | 平台配置、全部回调地址、旧配置候选及密钥状态 |
| `PUT /api/admin/member-login` | 带 revision 保存平台配置，防止并发覆盖 |
| `POST /api/admin/member-login/migrate` | 明确选择沿用一套旧站点配置，仅平台尚无配置时可用 |
| `POST /api/admin/member-login/test` | 在当前域名测试已保存的共享配置 |
| `POST /api/admin/member-login/key` | generate/import 登录加密密钥 |
| `POST /api/admin/member-login/key/export` | 下载密钥备份 |
| `GET /api/auth/providers` | 当前域名是否可使用平台 Google 登录 |
| `POST /api/auth/google/start` | 开始登录或绑定，返回 Google 授权 URL |
| `GET /api/auth/google/callback` | 消费事务、验证身份及创建会员会话 |
| `GET /api/v1/me/identities/google` | 当前会员的平台绑定状态及是否有本地密码 |
| `DELETE /api/v1/me/identities/google` | 确认本地密码后解除整个平台的绑定 |

平台配置接口忽略当前站点选择，不接受站点级凭据覆盖。后台按 Google / Facebook Tabs 切换。配置读取、保存和测试接口支持 `?provider=google|facebook`，省略时沿用 Google。两家开关、凭据和自动注册策略分别保存，加密主密钥共用且密文作用域隔离。Facebook 说明见 [facebook-login.md](facebook-login.md)。

自动测试使用本地签名及模拟 Google 服务，覆盖共享配置、跨站会员复用、权限隔离、旧配置及身份迁移、跨域回调拒绝、平台关闭和令牌校验。正式 Google 授权及域名审核需在真实部署环境联调。

Google 官方说明：[Web Server OAuth 与回调地址精确匹配要求](https://developers.google.com/identity/protocols/oauth2/web-server)。
