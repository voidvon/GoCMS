# 安全防护与宝塔 Nginx 接入

入口为 **平台管理 → 安全防护**（`/admin/security`）。Go 防护独立运行，Nginx 是可选的前置拦截适配器。接入采用一次性 root 初始化，自动创建一个安全规则文件并接入现有站点，之后由同一 GoCMS 程序的受限子命令同步名单、检查并重载 Nginx。升级自动建立安全表；扫描检测和 Nginx 同步默认关闭。

## 权限与范围

- 超级管理员进入「黑白名单」默认查看全局和各站点的规则。表格显示每条规则的归属，在「全平台」视图添加的规则对全平台生效。站点管理员仅能管理授权站点的名单。新增名单默认长期有效。
- 扫描规则按当前站点配置，覆盖数据库中配置的主域名、别名、通配域名及启用的独立语言域名。
- `security` 为查看权限，`security.manage` 为修改权限，均受用户组的站点授权限制。后台会话和 API Key 权限一致。
- 超级管理员可管理全局名单和全平台自动封禁，并配置可信代理、Nginx 接入和执行同步。已启用的全平台自动封禁策略仅超级管理员能修改。
- 优先级：全局白名单 → 全局封禁 → 本站白名单 → 本站封禁。自动封禁默认全平台，也可选择仅封禁当前站点。
- 名单支持 IPv4、IPv6、CIDR、到期时间和长期规则。禁止手动封禁包含当前操作者 IP 的网段。移除规则后保留历史。安全日志及过期历史保留 30 天。

## 扫描检测

在“扫描防护”配置当前站点的路径、窗口、次数、封禁范围与有效期，再启用防护。默认示例为 300 秒内 5 次，全平台封禁且长期有效；可关闭“长期有效”，设置 60 秒至 30 天的封禁时长。预置 `/server.key`、`/config.php`、`/.env`、`/.env.*`、`/.git/*`、`/.aws/credentials`，需按实际业务确认。

已有策略保留原来保存的时长；未记录封禁范围的旧策略保留本站范围，不自动扩大。仅有站点管理权限时，新策略使用本站封禁范围。

路径规范化后忽略大小写并完整匹配，仅末尾 `*` 表示前缀匹配。普通 404 不计入次数；后台、API 和证书验证路径不能作为扫描规则。命中路径从第一次起返回 403，达到阈值后封禁该 IP 对本站其他路径的访问。白名单不参加检测；被封禁后的请求不会延长到期时间。

记录首次探测、自动封禁及名单操作，重复探测只在内存计数。计数窗口有容量上限，进程重启重新计数；已形成的封禁保存到 SQLite，重启不丢失。IP/CIDR 查询使用内存索引，名单修改立即失效缓存，域名变化最长约 2 秒反映到 Go 防护。

## 真实客户端 IP

默认只信任 `127.0.0.1/32`、`::1/128`，适合同机 Nginx。外部连接传入的 `X-Forwarded-For` 不直接可信；来自可信代理时，从右向左解析到第一个不可信地址。无效或过长的链回退到连接来源。禁止配置覆盖所有 IP 的可信代理。

Nginx 应保留公开 Host，并覆盖客户端提供的转发域名，例如 `proxy_set_header X-Forwarded-Host $host;`。防护与现有公开路由使用同一域名选择方式，保证判断和实际服务的站点一致。

使用 CDN 时，先在 Nginx 配置 CDN 的可信地址及真实 IP 头，使 `$remote_addr` 是真实访客，再传给 Go。无法解析为真实访客的本机回环地址会拒绝扫描路径，但不会自动拉黑，避免误封整个本机反代。

## 首次接入宝塔

1. 在“Nginx 接入”填写并保存 Nginx 可执行文件、主配置、安全规则文件和 GoCMS 系统运行用户（通常为 `www`）。安全规则文件默认为 `/www/server/panel/vhost/nginx/gocms.conf`；不存在时自动创建，不需要手工建文件。后台站点的域名、别名及独立语言域名应与宝塔已有站点的 `server_name` 对应。
2. 在宝塔终端以 root 执行页面显示的初始化命令。页面自动填入当前程序与数据库的实际路径；默认部署也可执行 `./gocms nginx setup`，自定义数据库使用 `-db /绝对路径/site.db`。命令读取后台已保存的接入设置与当前名单，自动识别并备份对应站点，为其添加固定的拦截入口，保留原有监听端口、反向代理、证书及其他配置。即使同步尚未开启，也会使用站点域名完成接入，但不启用名单和扫描规则。
3. 初始化完成后，GoCMS 继续以 `www` 等普通用户运行。返回后台开启并保存 Nginx 同步，再点击“立即同步”，确认“已授权”和“已生效”。修改未保存时按钮显示“保存并同步”，先保存当前设置再执行同步。

初始化仅支持 Linux，服务器需安装 `sudo` 软件包，其中包含 `visudo`。缺少时命令会直接显示安装步骤：Ubuntu / Debian 执行 `apt update && apt install -y sudo`，Rocky / AlmaLinux / 新版 CentOS 执行 `dnf install -y sudo`，旧版 CentOS 执行 `yum install -y sudo`。安装后使用 `/usr/sbin/visudo -V` 验证，再执行原初始化命令并保留 `-db` 参数。程序会检查常见的 visudo 绝对路径，不依赖宝塔终端的 PATH 包含 sbin。

初始化会验证实际运行用户的受限免密调用，创建规则文件、备份配置、自动补齐 include、写入安全标记区、检查并平滑重载。已有直接、通配、相对路径或嵌套引用时沿用，不重复添加。站点与主配置继续由 root 管理，GoCMS 不需要取得宝塔配置目录的读写权限。

初始化将当前 GoCMS 可执行文件保存为 `/usr/local/libexec/gocms-nginx`，作为 root 所有的固定执行入口；这是同一程序的受限子命令，每次调用完成即退出。日常允许 `apply`、`events`、`status` 和 `config` 四种结构化操作，不运行额外常驻服务、不开启端口、不使用 Socket、不需要下载接入包。

授权保存在 `/etc/sudoers.d/gocms-nginx`，只允许指定系统用户执行固定路径及固定子命令；Nginx 路径与用户保存在 root 独占的 `/etc/gocms-security/control.json`，后台提交的路径必须与之完全一致。系统未加载 sudoers.d 时初始化会补齐引用并备份 sudoers，随后用 visudo 检查。授权检查、免密调用或 Nginx 检查失败时恢复本次修改的文件。

更改配置路径或运行用户前，先关闭同步并确认旧规则清理成功，保存新设置后重新执行初始化命令。普通后台更新不会覆盖 root 管理的执行入口；升级涉及 Nginx 管理逻辑时，也应使用新版本重新执行初始化命令以更新该入口。重复初始化沿用首次备份，并使用数据库当前名单，不会先清空已启用的封禁。

日常名单和扫描规则集中更新 `gocms.conf`，不生成第二份规则 include 或 logrotate 配置。原站点按路径摘要分别备份为 `/etc/gocms-security/vhost-*.before`；主配置备份为 `/etc/gocms-security/nginx.conf.before`；需要补齐 sudoers.d 引用时保存 `/etc/gocms-security/sudoers.before`。后续初始化与同步保留首次备份。探测日志为 `/var/log/gocms-security/probes.log`，由固定管理子命令读取，达到 20 MiB 时在原文件上清空以保留 Nginx 的日志句柄。

旧的独立代理服务、代理安装包及双 include 配置生成方式已移除。旧配置中的管理方式和 Socket 字段不再使用；原有名单、策略和同步确认记录保留。尚未执行新初始化时，后台提示执行 nginx setup。

## 配置文件与同步

新接入时，`gocms.conf` 为专用规则文件，只保存 `geo`、`map` 等生成规则，不创建新的虚拟主机或猜测 GoCMS 端口。初始化通过 `nginx -T` 读取实际加载文件清单，按数据库域名匹配已有站点，支持一个文件内多个 HTTP/HTTPS `server` 块。匹配站点加入固定的拦截与条件日志标记区；未匹配的站点保留原样。固定日志格式声明放在主配置 `http` 的开头，避免宝塔通配 include 顺序导致站点先于日志格式加载。

若升级前已选择完整的现有站点文件，则继续兼容原来的同文件标记区，不覆盖或迁移其中的代理与证书配置：

```nginx
# GOCMS-SECURITY-HTTP-BEGIN
# geo、map、log_format 等生成规则
# GOCMS-SECURITY-HTTP-END

server {
# GOCMS-SECURITY-SERVER-BEGIN
# 拦截与条件日志设置
# GOCMS-SECURITY-SERVER-END
    # 原站点配置
}
```

规则文件必须在主配置的 `http` 上下文中被引用，不能作为 `server` 块内的扩展文件。固定管理子命令每次同步通过 `nginx -T -c 主配置路径` 检查实际加载清单，支持引号、相对路径、通配与嵌套 include，并可修复后来被删除的引用和拦截入口。配置转储只在内存中读取，不保存到日志或返回后台；检查失败只返回有长度限制的诊断信息。修改后再次检查配置及规则确已加载，成功才重载；检查或重载失败恢复本次修改的规则、站点和主配置文件，首次创建的规则文件也会移除，不保留半套授权。

超级管理员可在“Nginx 接入 → 查看完整配置”读取 root 已授权的安全规则文件（默认 `gocms.conf`），显示实际完整内容、路径与修改时间，支持重新读取和复制全部。该入口读取磁盘文件，保留自定义注释及原有内容，不使用待同步片段拼接，不触发 Nginx 检查或重载；响应不缓存、不写日志。读取上限为 8 MiB，超过时明确报错，不截断内容。接口不能指定其他文件路径；未初始化、文件缺失或旧版受限入口尚不支持读取时，提示以 root 重新执行后台提供的 `nginx setup` 命令。

每次管理操作使用 root 所有的文件锁，避免后台同步、日志读取和重新初始化同时修改文件。识别到的站点路径和域名由 root 固定在授权配置中，后台不能提交其他文件路径扩大写入范围。新增独立站点文件、变更站点域名、正则或间接引用的 `server_name` 无法明确匹配时，需确认宝塔及后台域名配置后重新执行 `nginx setup`；命令会提示具体缺少的域名，不按文件名或行业路径猜测。旧版完整站点文件兼容方式仍要求唯一的顶层 `server` 块。

为保证共享 `server` 下的站点隔离，生成文件使用 `geo` 查询 IP/CIDR、域名 `map` 选择站点名单，并在代理前拒绝命中。域名与默认站点来自数据库，不依赖固定站点 ID 或行业路径。

同步使用结构化站点、域名、IP 与到期时间，由固定的 root 管理子命令校验输入、原子替换规则文件、检查授权站点的固定拦截入口、运行 Nginx 配置检查，再平滑重载。检查或重载失败恢复之前的文件，保留上一版确认。Nginx 检查与重载针对整个实例，不能只重载其中一个站点。

约每 15 秒同步，状态为未启用、待同步、已生效或同步失败。收到当前名单的确认才显示已生效；失败自动重试。关闭同步仍会发空名单清理旧规则，完成前显示待同步；重启保留上次确认，不掩盖未完成的清理。

GoCMS 在运行期间处理到期解封，停止后需恢复运行才能同步清理限时规则。实际生效和解封有约 15 秒批处理及平滑切换延迟，长连接可能继续由旧 Nginx 工作进程处理。

## Nginx 提前拦截的探测

现有 `.env`、`.git` 等规则可能在抵达 Go 前返回 404。接入配置额外生成条件日志，只将已启用扫描路径中没有选择上游的请求写入 `/var/log/gocms-security/probes.log`。已转发给 Go 的请求不重复计数。

GoCMS 通过受限管理子命令分页读取日志，按所属站点累计检测。读取支持轮转和未写完整的行；重启或轮转时可能重读最近日志，五分钟前的记录不进入检测。这不是计费或精确访问统计数据源。日志达到 20 MiB 时截断清理，保留 Nginx 当前打开的文件；持续攻击期间可能跳过较旧记录。

## 故障与回退

- 提示“尚未初始化”或“授权入口不可用”时，先保存后台接入设置，再在服务器以 root 执行页面显示的 nginx setup 命令。手动 include 无法替代系统授权。
- 提示“授权调用失败”时，确认后台填写的系统运行用户与实际 GoCMS 进程用户相同；初始化会自动以该用户验证 sudo，失败不会留下半套授权。
- 提示接入设置与 root 授权不一致时，保存所需路径后重新初始化；后台不能自行扩大 root 授权范围。
- 初始化拒绝由普通用户管理、允许其他用户写入的目标文件或其父目录，以及符号链接。配置文件、Nginx 可执行文件、授权入口与父目录应由 root 维护；不要把宝塔配置目录开放为可写。
- 检查或重载失败会恢复本次变更并保留上次同步确认。修正错误后后台会重试；也可点击“立即同步”。
- 关闭同步仍需完成一次空名单同步，清理完成才可更换路径；Go 侧扫描防护独立工作。
- 手工回退时，从 `/etc/gocms-security/` 的首次备份恢复对应配置，运行 Nginx 检查后重载。停用受限授权可由 root 移除 `/etc/sudoers.d/gocms-nginx`；这不会改变 Go 侧防护。

## 接口

- `GET/PUT /api/admin/security/policy`：本站扫描规则；`ban_scope=global|site` 控制自动封禁范围，默认 `global`；`ban_seconds=0` 表示长期有效（默认），其他值为 60–2592000 秒。
- `GET/POST /api/admin/security/entries`、`DELETE /api/admin/security/entries/{id}` 提供名单管理，支持 `scope=site|global`、`site_id`、`history=true` 和 `page`。超级管理员读取名单时可组合 `scope=global&include_sites=true`，在同一分页查看全局和各站点的规则。新增字段为 `network`、`kind=allow|deny`、`reason` 和可选的 RFC3339 `expires_at`。
- `GET /api/admin/security/events` 按 `scope=site|global` 查询安全日志，每页 50 条。
- `GET/PUT /api/admin/security/platform`：平台可信代理、Nginx 路径及 `run_user` 系统运行用户。
- `GET /api/admin/security/nginx`：同步状态、`setup` 初始化授权状态、`init_command` 实际初始化命令和待同步配置预览。
- `POST /api/admin/security/nginx/sync`：同步并等待确认。
- `GET /api/admin/security/nginx/config`：仅超级管理员可读取已授权安全规则文件全文，返回 `path`、`content`、`modified_at`；读取失败返回可读的 409 错误。

写操作要求同源 JSON。通用后台操作日志记录操作者、接口、IP 与结果。
