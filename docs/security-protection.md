# 安全防护与宝塔 Nginx 接入

入口为 **平台管理 → 安全防护**（`/admin/security`）。Go 防护独立运行，Nginx 是可选的前置拦截适配器。新配置默认由 GoCMS 直接管理一个站点配置文件、检查并重载 Nginx，无需额外程序。升级自动建立安全表；扫描检测和 Nginx 同步默认关闭。

## 权限与范围

- 超级管理员进入页面默认管理全平台名单，新增名单默认长期有效；站点管理员仅能管理授权站点的名单。
- 扫描规则按当前站点配置，覆盖数据库中配置的主域名、别名、通配域名及启用的独立语言域名。
- `security` 为查看权限，`security.manage` 为修改权限，均受用户组的站点授权限制。后台会话和 API Key 权限一致。
- 超级管理员可管理全局名单和全平台自动封禁，并配置可信代理、Nginx 接入和执行同步。已启用的全平台自动封禁策略仅超级管理员能修改。
- 优先级：全局白名单 → 全局封禁 → 本站白名单 → 本站封禁。自动封禁默认全平台，也可选择仅封禁当前站点。
- 名单支持 IPv4、IPv6、CIDR、到期时间和长期规则。禁止手动封禁包含当前操作者 IP 的网段。移除保留历史；安全记录及过期历史保留 30 天。

## 扫描检测

在“扫描防护”配置当前站点的路径、窗口、次数、封禁范围与有效期，再启用防护。默认示例为 300 秒内 5 次，全平台封禁且长期有效；可关闭“长期有效”，设置 60 秒至 30 天的封禁时长。预置 `/server.key`、`/config.php`、`/.env`、`/.env.*`、`/.git/*`、`/.aws/credentials`，需按实际业务确认。

已有策略保留原来保存的时长；未记录封禁范围的旧策略保留本站范围，不自动扩大。仅有站点管理权限时，新策略使用本站封禁范围。

路径规范化后忽略大小写并完整匹配，仅末尾 `*` 表示前缀匹配。普通 404 不计入次数；后台、API 和证书验证路径不能作为扫描规则。命中路径从第一次起返回 403，达到阈值后封禁该 IP 对本站其他路径的访问。白名单不参加检测；被封禁后的请求不会延长到期时间。

记录首次探测、自动封禁及名单操作，重复探测只在内存计数。计数窗口有容量上限，进程重启重新计数；已形成的封禁保存到 SQLite，重启不丢失。IP/CIDR 查询使用内存索引，名单修改立即失效缓存，域名变化最长约 2 秒反映到 Go 防护。

## 真实客户端 IP

默认只信任 `127.0.0.1/32`、`::1/128`，适合同机 Nginx。外部连接传入的 `X-Forwarded-For` 不直接可信；来自可信代理时，从右向左解析到第一个不可信地址。无效或过长的链回退到连接来源。禁止配置覆盖所有 IP 的可信代理。

Nginx 应保留公开 Host，并覆盖客户端提供的转发域名，例如 `proxy_set_header X-Forwarded-Host $host;`。防护与现有公开路由使用同一域名选择方式，保证判断和实际服务的站点一致。

使用 CDN 时，先在 Nginx 配置 CDN 的可信地址及真实 IP 头，使 `$remote_addr` 是真实访客，再传给 Go。无法解析为真实访客的本机回环地址会拒绝扫描路径，但不会自动拉黑，避免误封整个本机反代。

## 首次接入宝塔

1. 在“Nginx 接入”选择 **GoCMS 直接管理**，填写 Nginx 可执行文件、主配置和实际代理 GoCMS 的宝塔站点配置，例如 `/www/server/panel/vhost/nginx/gocms.conf`。
2. 页面显示 GoCMS 当前的系统运行用户。该用户需要具备读取与写入所选站点配置、写入备份目录 `/etc/gocms-security/` 和日志目录 `/var/log/gocms-security/`、运行 Nginx 配置检查和向主进程发送重载信号的权限。主配置路径只用于执行检查和重载，不会由 GoCMS 写入。后台不能自动提升系统权限；无权限时会显示具体错误。
3. 开启 Nginx 同步并保存，点击“立即同步”。首次同步备份站点配置，在同一文件内添加两处安全标记区，检查通过后平滑重载，保留站点原有证书、反代及其他设置。
4. 确认状态为“已生效”。之后名单、策略与解封均由后台管理，约每 15 秒自动同步，配置未变化时不重载。

直接管理只写所选站点配置这一份 Nginx 配置，不生成额外的 Nginx include 文件，也不修改主配置和 logrotate 配置。备份和探测日志是运行数据，分别保存在上述目录。使用已有宝塔 Nginx，不需要重新安装 Nginx、安装 systemd 服务或监听 Socket。

## 可选独立代理（兼容模式）

已使用旧版代理接入的配置保留代理模式，避免升级时改变权限模型。需要让 GoCMS 保持普通系统用户运行时，也可以继续选用该模式。

1. 在“Nginx 接入”填写并保存 Nginx 可执行文件、主配置、宝塔站点配置、GoCMS 系统运行用户和 Socket。预置常见宝塔路径，站点配置须选实际代理 GoCMS 的文件。
2. 下载接入 ZIP，解压到服务器。`agent.json` 来自后台已保存的参数，不需要手工修改。
3. 在服务器以 root 执行 `sh install.sh /绝对路径/site`，使用升级后的 GoCMS 可执行文件。首次安装需要 Linux/systemd，GoCMS 本身继续以普通用户运行。
4. 返回后台选择“独立代理（兼容模式）”，开启同步并保存，点击“立即同步”，确认显示“已生效”。

安装器复制自身到 `/usr/local/libexec/gocms-security-agent`，安装 `gocms-security-agent.service`；配置由 root 保存在 `/etc/gocms-security/agent.json`。更新同步器或修改安装路径、系统运行用户后，需要用新版程序重新安装。

服务只监听本机 Unix Socket，权限 0600，仅指定的 GoCMS 系统用户和 root 可连接；Socket 所在目录不能允许其他用户写入。不开放公网管理端口，不需要宝塔 API 密钥。安装是一次明确的 root 操作，普通后台接口不能执行安装。

尚未安装代理、也没有成功同步过名单时，可以直接在后台切换到“GoCMS 直接管理”。已有生效规则时，先关闭同步并确认清理完成，再切换管理方式；切换到直接管理前还需停止旧代理服务，避免两个进程管理同一套文件。

## 配置文件与同步

直接管理将以下两处标记区写入同一个站点文件，名单查询与日志格式放在 `server` 之前，拦截与日志设置放在 `server` 内。更新只替换标记区，保留文件其他内容：

```nginx
# GOCMS-SECURITY-HTTP-BEGIN
# geo、map、log_format 等生成规则
# GOCMS-SECURITY-HTTP-END

server {
# GOCMS-SECURITY-SERVER-BEGIN
# 拦截与条件日志设置
# GOCMS-SECURITY-SERVER-END
    # 原站点配置
}
```

站点文件必须在主配置的 `http` 上下文中被引用，这是宝塔常见的站点加载方式；不能将其作为 `server` 块内的扩展文件。无法通过 `nginx -t` 时恢复原站点文件。检测到多个顶层 `server` 或标记不完整时拒绝猜测。

旧版直接管理写入的站点 include 会在该站点文件中自动移除，改用新标记区；原主配置中的旧 include 保留且不再参与本站拦截，新规则使用独立变量名以避免冲突。GoCMS 不改写旧主配置，也不清理其仍引用的旧文件。

独立代理兼容模式仍使用原来的两个专用 include：

```nginx
# http 块
include /etc/gocms-security/http.conf;

# server 块
include /etc/gocms-security/server.conf;
```

支持重复安装；目标文件存在多个顶层目标块时会拒绝猜测。第一版接入针对一个主配置和一个站点 `server` 文件；多个 CMS 站点可以共享该 `server`，受保护域名必须已被该 Nginx 站点代理。

为保证共享 `server` 下的站点隔离，生成文件使用 `geo` 查询 IP/CIDR、域名 `map` 选择站点名单，并在代理前拒绝命中。域名与默认站点来自数据库，不依赖固定站点 ID 或行业路径。

同步使用结构化站点、域名、IP 与到期时间。直接模式由 GoCMS 以当前系统用户更新站点文件，代理模式通过本机 Socket 更新专用 include；都先校验输入、原子替换、运行指定 Nginx 的配置检查，再平滑重载。检查或重载失败恢复之前的文件，保留上一版确认。Nginx 检查与重载针对整个实例，不能只重载其中一个站点。

约每 15 秒同步，状态为未启用、待同步、已生效或同步失败。收到当前名单的确认才显示已生效；失败自动重试。关闭同步仍会发空名单清理旧规则，完成前显示待同步；重启保留上次确认，不掩盖未完成的清理。

直接模式在 GoCMS 运行期间处理到期解封，GoCMS 停止后需恢复运行才能同步清理限时规则。代理模式独立检查到期时间，CMS 暂停时也能清除过期封禁。实际生效和解封有约 15 秒批处理及平滑切换延迟，长连接可能继续由旧 Nginx 工作进程处理。

## Nginx 提前拦截的探测

现有 `.env`、`.git` 等规则可能在抵达 Go 前返回 404。接入配置额外生成条件日志，只将已启用扫描路径中没有选择上游的请求写入 `/var/log/gocms-security/probes.log`。已转发给 Go 的请求不重复计数。

直接模式由 GoCMS 读取本机日志，代理模式通过 Socket 分页读取，按所属站点累计检测。读取支持轮转和未写完整的行；重启或轮转时可能重读最近日志，五分钟前的记录不进入检测。这不是计费或精确访问统计数据源。直接模式在读取时发现日志达到 20 MiB 会截断清理，保留 Nginx 当前打开的文件；持续攻击期间可能跳过较旧记录。代理模式通过 logrotate 每日或达 20 MiB 轮转，保留 3 份。

## 故障与回退

- 直接模式无权限时，根据错误中的系统用户检查配置与目录写入、Nginx 检查与重载权限。运行 `nginx -t` 需要读取配置引用的证书与日志，只有站点配置文件写权限仍可能不足。
- 代理模式出现“未找到同步代理的 Socket”通常表示尚未安装代理、服务未启动或 Socket 路径不一致。也可按上述步骤切换到直接管理。
- “无权访问”表示 GoCMS 实际进程用户与接入包的运行用户不一致，需更正后台参数、重新下载并安装接入包；不要将 Socket 开放给所有用户。
- 可在服务器执行 `systemctl status gocms-security-agent --no-pager` 和 `journalctl -u gocms-security-agent -n 50 --no-pager` 检查服务与日志。
- 查看后台同步错误和 `systemctl status gocms-security-agent`，确认后台与服务的 Socket 一致，运行用户与 GoCMS 实际系统用户一致。
- Nginx 提前拦截不进入 GoCMS 访问统计，使用“安全记录”及专用日志排查。
- 先关闭同步并确认空名单清理成功，再停止服务；Go 防护仍独立生效。
- 直接模式撤销时先关闭同步并确认清理完成；需要完全移除标记区时，可恢复 `/etc/gocms-security/server.conf.before` 对应的站点配置，检查后重载。代理模式还需停止代理服务，合并恢复 `nginx.conf.before` 和 `server.conf.before`。备份为首次接入快照，恢复前应合并宝塔之后的其他配置改动。
- 独立代理程序和系统配置只能由 root 管理。直接管理按 GoCMS 当前进程的操作系统权限执行固定的 Nginx 检查与重载命令，不接受后台提交任意命令文本。

## 接口

- `GET/PUT /api/admin/security/policy`：本站扫描规则；`ban_scope=global|site` 控制自动封禁范围，默认 `global`；`ban_seconds=0` 表示长期有效（默认），其他值为 60–2592000 秒。
- `GET/POST /api/admin/security/entries`、`DELETE /api/admin/security/entries/{id}`：名单；筛选 `scope=site|global`、`site_id`、`history=true`、`page`。新增字段为 `network`、`kind=allow|deny`、`reason`、可选 RFC3339 `expires_at`。
- `GET /api/admin/security/events`：同一范围的安全记录，每页 50 条。
- `GET/PUT /api/admin/security/platform`：平台可信代理及安装参数。
- `GET /api/admin/security/nginx`：状态和待同步配置预览。
- `POST /api/admin/security/nginx/sync`：同步并等待确认。
- `POST /api/admin/security/nginx/install`：下载接入包。

写操作要求同源 JSON。通用后台操作日志记录操作者、接口、IP 与结果。
