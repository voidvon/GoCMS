# 共享地址目录

地址选择是 CMS 的独立基础服务，不依附于支付商、分类、主题或某个站点。国家、一级行政区和城市目录供所有站点共享；目前 storefront 的实体商品结算页接入，其他模块可复用同一查询接口。

## 后台使用

使用超级管理员登录，进入「平台管理 → 地址数据」。

- 首次启动自动建立内置国家目录，无需 API Key。行政区和城市需在后台初始化。
- 点击「下载并更新 GeoNames」，由服务端下载官方 `countryInfo.txt`、`admin1CodesASCII.txt`、`cities500.zip` 并导入。任务后台运行，页面轮询进度，关闭页面不影响导入。
- 无法联网时，在后台上传版本名称、行政区 TXT、城市 ZIP 或 TXT。国家文件可选，留空使用随程序提供的国家快照。文件必须是 GeoNames 原始制表符格式；不接受任意 CSV、嵌套 ZIP、符号链接或多个城市 TXT。
- 上传请求总大小最多 64 MiB；城市 ZIP 展开最多 512 MiB；最多 300 个国家、10,000 个一级行政区、1,000,000 个城市。一次仅允许一个导入任务。
- 完整校验及导入成功后，事务内切换当前目录。任何失败均回滚，继续使用旧目录。保留新版本与导入前使用的版本，可在后台切换。更新和回退均不改写已有订单的地址。
- 更新操作属于平台操作，仅超级管理员的后台登录会话可执行；普通管理员、会员、API Key 均无权管理。导入和下载使用固定目录及官方来源，不接受任意下载地址。

源码中只附带 GeoNames 国家参考文件，不附带全球城市包。默认城市包 `cities500` 包含人口超过 500 的城市及符合该包规则的行政中心，不能视为全球完整地址库。无需定期联网才能结算；更新频率由管理员决定。

## 数据与更新边界

`backend/internal/geography` 持有独立 SQLite 数据库，默认位于运行数据目录的 `geography/geography.sqlite`。与订单及内容数据库分开，使用 WAL；各个目录版本有独立 ID。大包流式读取并写入事务，不在前端加载全球数据，也不将原始 ZIP 解压到公开目录。

导入期间查询继续读取旧版，切换后新请求读取新版。前端依次根据国家和可选行政区查询城市，异步请求可取消，搜索防抖；返回数量有限。导入任务状态暂存在服务端内存中；进程退出会取消任务，数据库事务回滚，重启后仍使用最近成功启用的目录。当前实现面向单进程 GoCMS，多副本部署需将任务互斥和状态迁移为持久化任务队列。

备份时数据库属于外置运行数据，不随二进制升级覆盖。SQLite 使用 WAL，运行期间不要仅复制主文件；应在服务停止后备份完整目录，或使用 SQLite 的一致性备份机制。

## 接口

公开 GET 接口不要求会员登录：

| 地址 | 参数 | 含义 |
| --- | --- | --- |
| `/api/geography/countries` | 无 | 国家代码与名称 |
| `/api/geography/regions` | `country=US` | 国家下的一级行政区 |
| `/api/geography/cities` | `country=US&region=CA&q=San` | 可选行政区、城市搜索，最多 30 条，优先人口较多的地点 |

返回 `{items, source, license}`。条目包含 `id`、`name`，按类型附带 `country`、`region`、`region_name`、`ascii`。城市按原始名称、ASCII 名称及文件中的别名搜索；不保证每个城市都有每种语言的别名。

超级管理员接口：GET `/api/admin/geography` 查看版本与任务；POST `/download` 开始官方更新；POST `/import` 上传 multipart 字段 `version`、`countries`（可选）、`regions`、`cities`；POST `/activate` 接收 JSON `{id}` 切换版本。所有 POST 路径均以 `/api/admin/geography` 为前缀。

## 地址模型与多语言

国家保存两位国家代码；国家展示名通过 `Intl.DisplayNames` 跟随 storefront 当前语言，缺失时回退 GeoNames 名称。语言偏好与收货国家独立，不根据语言自动填写国家。城市和行政区显示数据源名称，支持别名搜索；第一版不宣称城市名称已完整翻译成 11 种语言。

GeoNames 的一级行政区代码并非统一的 ISO 3166-2 代码，只用于目录内部联动。订单仍保存原有 `{country, state, city, street, postcode}` 地址快照，其中 `state`、`city` 为用户选择或填写的名称；不把内部城市 ID 或行政区代码当作支付商的地址编码。将来支付商需要专属格式时，由支付适配器完成映射。

结算页保留国家代码、城市、行政区手动输入，目录加载失败或等待时也能继续填写。不会因某个城市未收录就禁止用户下单。切换国家会清空已选行政区和城市，切换行政区会清空已选城市，旧请求不会覆盖新选择。现有订单字段仍遵守原有长度约束；名称超过支付地址长度限制的候选项会提示手动填写，不自动截断。

目录只辅助输入，不验证街道、邮编、真实可投递性或商家的配送范围。运费、配送区域、地址簿和自动补全街道属于后续独立能力。
