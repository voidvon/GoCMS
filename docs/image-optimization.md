# 图片上传与服务端优化

内容封面、多图字段、正文编辑器、素材库和后台订单图片共用 `POST /api/admin/media`。支持 JPEG、PNG、GIF、WebP，以及 HEVC 编码的 HEIC/HEIF；根据文件实际内容识别格式，不依赖文件名或客户端 MIME 类型。SVG、AVIF 和其他 HEIF 编码不在此接口的支持范围内。

在后台「站点管理 → 站点参数配置」设置「上传图片自动优化」和「压缩质量」。配置按站点隔离，沿用站点配置接口的登录与站点访问权限，保存后立即对新上传生效，不需要重新发布或编辑服务器文件。默认开启，质量为 80。

优化流程：

1. 校验源文件不超过 10 MiB、宽高均不超过 12000、总像素不超过 4800 万，然后才解码像素。关闭自动优化也必须通过像素解码校验，损坏或截断的文件返回错误，不创建附件文件或记录。
2. 纠正 JPEG、WebP 中记录的 EXIF 方向；HEIC 解码器处理自身方向信息。
3. 生成 WebP、JPEG（仅不透明图片）、无损 PNG，与原图比较文件大小。至少节省 512 字节才采用新文件，否则保留原图字节。不改变像素分辨率，方向纠正可能交换宽高。
4. GIF、动画 WebP、APNG 校验所有帧后原样保存，保留动画和播放时序。最多 200 帧，累计画布像素（画布宽 × 画布高 × 帧数）不超过 4800 万，超限在多帧解码前拒绝。HEIC/HEIF 仅接受单张照片，输出浏览器可显示的格式，即使关闭自动优化也会转换；图片序列在解码前拒绝，包括使用普通图片品牌但包含电影轨道的文件。
5. 像素解码失败直接报错；候选编码失败时，保留已校验的原图或继续比较其他成功候选；HEIC 无法转换则报错。候选输出缓冲区和最终文件均不得超过 10 MiB。
6. 用最终文件的格式确定扩展名和 MIME 类型，并保存实际文件大小、尺寸和 SHA-256。素材库上传成功时显示节省的空间。

WebP 与 JPEG 候选采用有损编码，PNG 候选采用无损编码。质量参数控制 WebP，JPEG 在此基础上加 2（上限 100）。优化不会备份原图，不会批量修改已上传文件或既有 URL；需要保留原文件时先关闭自动优化（HEIC/HEIF 除外）。

与旧 Node.js 项目采用相同的体积选择策略，但编码结果不保证相同：使用 Go 的 JPEG/PNG 编码器及嵌入的 WebP/HEIC 实现，PNG 不做旧项目中的调色板量化，不依赖 sharp、系统 libvips 或服务器转换命令。支持 `CGO_ENABLED=0` 的单文件发布；构建与 Release 使用 `nodynamic` 标签，完全不加载系统图片库，测试也覆盖同一路径。

图片头部检查、解码、编码在当前可执行文件启动的一次性子进程中执行，不需要安装额外程序。服务入口在初始化数据库和 HTTP 服务之前处理内部 `__gocms-image-worker` 调用，图片通过 stdin/stdout 传递，不使用公开临时文件。每个服务进程最多运行一个图片子进程、保留四个等待任务；队列已满或等待超过 5 秒返回 503，可稍后重试。单次处理最多 30 秒，超时返回 504；请求取消或超时会终止并回收子进程，然后释放处理槽，不留下后台编码任务。

子进程使用单个 Go 执行线程、512 MiB 的 Go 软内存目标，并每 25ms 检查堆占用，超过 768 MiB 时退出并拒绝该图片。该检查是堆内存监控，允许采样间隔内的瞬时超出，不是操作系统 RSS 硬配额；文件大小、像素、动画帧数和输出缓冲限制共同约束解码与编码资源。子进程退出会释放其编码器和 WASM 内存，不在服务中长期保留。

站点配置字段：`image_optimization_enabled` 为字符串 `"true"` / `"false"`；`image_optimization_quality` 为字符串形式的 1–100 整数。非法值在整笔配置保存前拒绝。
