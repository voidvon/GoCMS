# 订单管理与交付

后台左侧一级入口 **订单管理**，地址 `/admin/orders`。订单、物流公司历史选项和操作记录按当前管理站点隔离。支付渠道与支付回调保留在 **支付管理**。

## 后台创建收款订单

1. 在 **支付管理** 配置支付密钥并启用收款渠道，确认渠道的 HTTPS 公开地址能访问本站 `/shop/` 和交易 API。
2. 进入 **订单管理 → 创建收款订单**，选择收款渠道，填写客户姓名、邮箱、交付通知邮件语言和明细。点击 **搜索现有商品 / 服务**，按名称、内容编号、SKU 或规格搜索本站已开启在线销售的可购买内容，分页选择具体规格，自动带入名称、类型、图片及渠道币种报价；重复添加同一规格会累加数量。也可手动添加独立明细。支持服务、数字商品、实物及多条明细；手动明细需填写约定单价、数量和收银台图片，可选本站素材或公开 HTTPS 图片，有 `media` 权限时可直接上传或打开素材库。实物订单还要求电话、两位大写国家代码、城市、街道和邮编。
3. 已选规格允许调整本单单价和数量，名称、类型、图片来自原内容；需自行编辑这些信息时可点击 **改为手动明细**。服务端保存时重新校验所选规格、销售状态及站点归属，保留内容、SKU 和规格快照；按渠道币种计算总额，不修改商品目录及原商品价格。搜索报价复用多币种的固定价格和汇率配置，无法报价时不可直接添加。切换收款币种后，原币种明细需重新选择规格或重新填写约定单价才能提交，避免直接套用不同币种数字。金额采用最小货币单位整数；JPY 不接受非零小数，其他币种支持两位小数。重复提交相同请求不会重复创建订单。
4. 创建后自动打开详情并生成完整付款链接，复制后发送给客户。链接使用渠道已配置的公开地址，形式为 `/shop/pay/<订单号>#token=<随机凭证>`，无需发布主题页面。客户无需注册或登录，打开即可核对明细、金额及收货资料，再进入原有托管收银台；付款后返回本订单，支持主动同步状态、自动刷新和查看交付进度。
5. 完整链接仅在生成后的本次详情中显示，关闭后不再回显。未付款时可以 **生成 / 重置付款链接**，旧链接立即失效；已付款后保留原链接查看状态，不允许再次付款或重置。创建和重置均记录操作人及时间，使用订单版本防止旧页面重置新链接。

持有链接即可查看这一张订单的客户信息，请仅发送给对应客户。凭证使用 32 字节安全随机数，数据库仅保存哈希，通过 URL 片段传递给浏览器，再以请求头访问订单，不进入服务端 URL 和查询参数。浏览器按站点和订单保存当前标签页的会话凭证，用于从收银台返回后继续查看；如果清除了浏览器会话，请重新打开商家发来的完整链接。链接不授予会员账户、其他订单或订单列表的访问权。后台收款订单不会按邮箱自动绑定会员，仍在后台统一处理发货、完成和退款，客户通过原链接跟进。

## 使用流程

1. 搜索订单号、收货人、电话或物流单号，可按待付款、待交付、部分交付、已交付、已完成、已退款筛选。
2. 进入详情检查商品快照及收货信息。新实物订单结算要求电话；历史订单可在首次发货前补录收货人、电话和地址，填写修改原因。
3. 已付款且无待确认退款时创建发货单，选择本次商品数量。物流公司可从本站历史记录选择或手动填写。快递填写物流公司、单号，可填 HTTP(S) 查询网址、交付时间、客户备注、内部备注；自提及无需物流的交付不要求单号。实物不能选择无需物流，非实物不能选择快递配送。
4. 支持一个订单多次发货，每行累计不能超过订购数量。全部交付后显示“已发货 / 交付”，客户已收到商品或服务后再单独“确认完成”。历史已完成订单不补造发货记录。
5. 物流信息可更正，必须填写原因；商品及交付数量不可在更正中修改。订单详情保留更正前后值、操作人及时间。当前阶段不提供删除或撤销发货单。
6. 支付及全额退款可在订单详情同步。退款不删除交付历史，不自动处理退货。部分退款、退货入库、物流轨迹订阅、电子面单及批量发货留待后续。

## 权限

在平台管理的用户组中分配站点权限：`orders` 查看订单；`orders.create` 创建收款订单和生成 / 重置付款链接；`orders.ship` 创建发货单；`orders.shipping.edit` 更正物流；`orders.recipient.edit` 补录收货信息；`orders.complete` 确认完成；`orders.refund` 发起和同步退款。操作权限同时要求 `orders`，超级管理员具备全部权限。订单管理支持后台会话或 API Key，按所属管理员校验相同的站点与操作权限。写操作保留同源校验。

后台创建接口为 `POST /api/admin/orders`，请求头携带至少 16 字符的 `Idempotency-Key`，请求体包含 `account_id`、`customer_name`、`email`、`language`、`address`、`items`。手动明细为 `{name, kind, price, quantity, image_url}`，`price` 是十进制金额字符串；选择现有规格时传 `variant_id` 和 `currency`，服务端从对应规格读取名称、类型、图片、内容与规格信息，单价仍是本单约定价。`GET /api/admin/orders/catalog?account_id=<渠道ID>&q=<关键词>&page=1` 提供分页规格搜索与报价，返回 `items`、`has_more`，要求 `orders`、`orders.create` 权限，支持后台会话或 API Key。`GET /api/admin/orders/creation-options` 提供本站已启用渠道的必要信息；`POST /api/admin/orders/<订单号>/payment-link` 携带 `{revision}` 返回一次性的完整 `payment_url`。公开查询、付款和同步复用 `/api/commerce/orders/<订单号>`、其 `/pay` 和 `/sync` 子路由，专属链接访问需携带 `X-Order-Token`；原会员订单仍仅允许所属会员访问。

旧支付接口的读订单、退款保持兼容；旧交付状态接口不允许处理实物或已有发货单的订单，也不允许重开已完成订单。旧服务订单的状态更新仍保留兼容。

## 前台与隐私

会员只能查看自己的本站会员订单；后台收款订单需持有独立付款凭证。订单详情列出包裹、交付商品及数量、时间、客户备注；支持复制单号、打开物流查询地址。内部备注、操作人及审计详情只在后台返回。结算电话、物流及交付状态文案覆盖现有 11 种语言，数量、日期沿用当前语言格式化，支持 RTL。

## 邮件通知

复用 **平台管理 → 邮件设置** 的全局 SMTP 开关。创建发货单时邮件可用则在同一事务中记入持久队列；关闭时记录为跳过，不会日后补发旧订单。后台维护任务每分钟轮询，每批最多两封，失败间隔五分钟重试，最多五次；失败不回滚发货。发送前关闭邮件则跳过排队消息。订单详情展示邮件状态。

邮件采用下单时 storefront 当前语言，历史订单或未知语言回退英语，支持现有 11 种语言。邮件仅含订单号、物流及客户备注，不含内部备注、地址或后台链接。更正物流不会重复触发首次发货邮件。

SMTP 为至少一次发送：服务在邮件已投递但尚未记录成功时崩溃，恢复后可能重发；不能保证外部邮件系统恰好一次投递。真实投递仍需管理员配置并测试 SMTP。

## 数据及一致性

启动时自动添加订单版本、下单语言、发货单、发货明细、订单事件表。原订单、商品快照及支付退款记录保持原值。发货使用订单版本、事务内数量检查和每订单唯一请求键；原请求重试返回同一发货单，不重复分配数量或通知。物流更正、收货信息修改、确认完成均检查版本，过期页面需刷新后再操作。
