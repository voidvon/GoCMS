# 订单管理与交付

后台左侧一级入口 **订单管理**，地址 `/admin/orders`。订单、物流公司历史选项和操作记录按当前管理站点隔离。支付渠道与支付回调保留在 **支付管理**。

## 使用流程

1. 搜索订单号、收货人、电话或物流单号，可按待付款、待交付、部分交付、已交付、已完成、已退款筛选。
2. 进入详情检查商品快照及收货信息。新实物订单结算要求电话；历史订单可在首次发货前补录收货人、电话和地址，填写修改原因。
3. 已付款且无待确认退款时创建发货单，选择本次商品数量。物流公司可从本站历史记录选择或手动填写。快递填写物流公司、单号，可填 HTTP(S) 查询网址、交付时间、客户备注、内部备注；自提及无需物流的交付不要求单号。实物不能选择无需物流，非实物不能选择快递配送。
4. 支持一个订单多次发货，每行累计不能超过订购数量。全部交付后显示“已发货 / 交付”，客户已收到商品或服务后再单独“确认完成”。历史已完成订单不补造发货记录。
5. 物流信息可更正，必须填写原因；商品及交付数量不可在更正中修改。订单详情保留更正前后值、操作人及时间。当前阶段不提供删除或撤销发货单。
6. 支付及全额退款可在订单详情同步。退款不删除交付历史，不自动处理退货。部分退款、退货入库、物流轨迹订阅、电子面单及批量发货留待后续。

## 权限

在平台管理的用户组中分配站点权限：`orders` 查看订单；`orders.ship` 创建发货单；`orders.shipping.edit` 更正物流；`orders.recipient.edit` 补录收货信息；`orders.complete` 确认完成；`orders.refund` 发起和同步退款。操作权限同时要求 `orders`，超级管理员具备全部权限。订单管理只接受后台会话，不接受 API Key。写操作校验同源请求。

旧支付接口的读订单、退款保持兼容；旧交付状态接口不允许处理实物或已有发货单的订单，也不允许重开已完成订单。旧服务订单的状态更新仍保留兼容。

## 前台与隐私

会员只能查看自己的本站订单。订单详情列出包裹、交付商品及数量、时间、客户备注；支持复制单号、打开物流查询地址。内部备注、操作人及审计详情只在后台返回。结算电话、物流及交付状态文案覆盖现有 11 种语言，数量、日期沿用当前语言格式化，支持 RTL。

## 邮件通知

复用 **平台管理 → 邮件设置** 的全局 SMTP 开关。创建发货单时邮件可用则在同一事务中记入持久队列；关闭时记录为跳过，不会日后补发旧订单。后台维护任务每分钟轮询，每批最多两封，失败间隔五分钟重试，最多五次；失败不回滚发货。发送前关闭邮件则跳过排队消息。订单详情展示邮件状态。

邮件采用下单时 storefront 当前语言，历史订单或未知语言回退英语，支持现有 11 种语言。邮件仅含订单号、物流及客户备注，不含内部备注、地址或后台链接。更正物流不会重复触发首次发货邮件。

SMTP 为至少一次发送：服务在邮件已投递但尚未记录成功时崩溃，恢复后可能重发；不能保证外部邮件系统恰好一次投递。真实投递仍需管理员配置并测试 SMTP。

## 数据及一致性

启动时自动添加订单版本、下单语言、发货单、发货明细、订单事件表。原订单、商品快照及支付退款记录保持原值。发货使用订单版本、事务内数量检查和每订单唯一请求键；原请求重试返回同一发货单，不重复分配数量或通知。物流更正、收货信息修改、确认完成均检查版本，过期页面需刷新后再操作。
